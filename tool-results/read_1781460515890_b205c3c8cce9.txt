    10→
    11→## How This Roadmap Works
    12→
    13→This roadmap uses **two parallel tracks** that proceed independently but converge:
    14→
    15→- **Releases** (v2.1, v2.2, ...) — user-facing feature deliveries, each produces a shippable build
    16→- **Sprints** (Sprint 1, 2, ...) — infrastructure/RBAC work that enables platform-scale features
    17→
    18→A release may span multiple sprints. A sprint may contribute to multiple releases. Dependencies are explicitly mapped.
    19→
    20→```
    21→Releases:   v2.0 ─── v2.1 ─── v2.2 ─── v2.3 ─── v2.4 ─── v2.5 ─── v2.6
    22→                \       \       \                \       \
    23→Sprints:     S1+S2 ──  S3 ──  S3B ─── S4 ─── S5 ─── S6 ─── S7 ─── S8
    24→```

   872→## Key Implementation Principles
   873→
   874→1. **Use Design Tokens** — All colors, spacing, typography from `lib/core/tokens/`
   875→2. **Use Enterprise Components** — KlasivoButton, KlasivoCard, KlasivoBadge, etc.
   876→3. **Use Feature Flags** — Gate new features behind flags
   877→4. **Use Permission Gates** — `KlasivoPermissionGate`, `KlasivoRoleGate`
   878→5. **Use Event Bus** — Decouple feature modules via typed events
   879→6. **Follow Clean Architecture** — Services → Providers → Screens
   880→7. **Soft Delete** — All entities use `isArchived` + `archivedAt` pattern
   881→8. **Riverpod Functional Style** — Functional providers, not Notifiers (except where needed)
   882→9. **Firestore Security** — Role-based rules with field-level security
   883→10. **RBAC is Platform-Agnostic** — Permissions know role/permission/scope, not Web/Mobile/Dashboard
   884→11. **Fail-Closed Authorization** — Missing metadata = DENY. Unknown scope = DENY. Empty arrays = DENY.
   885→12. **Server-Side Role Determination** — Never trust client-sent role values; derive from auth claims
