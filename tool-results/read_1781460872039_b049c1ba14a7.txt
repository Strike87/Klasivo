    10→
    11→## How This Roadmap Works
    12→
    13→This roadmap uses **three parallel tracks** that proceed independently but converge:
    14→
    15→- **Releases** (v2.1, v2.2, ...) — user-facing feature deliveries, each produces a shippable build
    16→- **Sprints** (Sprint 1, 2, ...) — infrastructure/RBAC work that enables platform-scale features
    17→- **Migration Phases** (M1–M8) — zero-downtime migration from MVP to production SaaS platform
    18→
    19→A release may span multiple sprints. A sprint may contribute to multiple releases. Dependencies are explicitly mapped.
    20→
    21→```
    22→Releases:      v2.0 ─── v2.1 ─── v2.2 ─── v2.3 ─── v2.4 ─── v2.5 ─── v2.6 ─── v3.0
    23→                   \       \       \                \       \       \        \
    24→Sprints:        S1+S2 ──  S3 ──  S3B ─── S4 ─── S5 ─── S6 ─── S7 ─── S8 ─── S9+
    25→                                                                     \
    26→Migration:                                             M1 ── M2 ── M3 ── M4 ── M5 ── M6 ── M7 ── M8
    27→```

  1247→## Key Implementation Principles
  1248→
  1249→1. **Use Design Tokens** — All colors, spacing, typography from `lib/core/tokens/`
  1250→2. **Use Enterprise Components** — KlasivoButton, KlasivoCard, KlasivoBadge, etc.
  1251→3. **Use Feature Flags** — Gate new features AND migration steps behind flags
  1252→4. **Use Permission Gates** — `KlasivoPermissionGate`, `KlasivoRoleGate`
  1253→5. **Use Event Bus** — Decouple feature modules via typed events
  1254→6. **Follow Clean Architecture** — Services → Providers → Screens
  1255→7. **Soft Delete** — All entities use `isArchived` + `archivedAt` pattern
  1256→8. **Riverpod Functional Style** — Functional providers, not Notifiers (except where needed)
  1257→9. **Firestore Security** — Role-based rules with field-level security
  1258→10. **RBAC is Platform-Agnostic** — Permissions know role/permission/scope, not Web/Mobile/Dashboard
  1259→11. **Fail-Closed Authorization** — Missing metadata = DENY. Unknown scope = DENY. Empty arrays = DENY.
  1260→12. **Server-Side Role Determination** — Never trust client-sent role values; derive from auth claims
  1261→13. **Shared Models, No Duplication** — Monorepo packages ensure single source of truth for all apps
  1262→14. **Migration is Feature-Flagged** — Every migration step can be rolled back per-org without downtime
  1263→15. **Immutable Audit Trail** — Every mutation logged, append-only, no deletion
