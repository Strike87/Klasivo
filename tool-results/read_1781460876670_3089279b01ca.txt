    11→    11→## How This Roadmap Works
    12→    12→
    13→    13→This roadmap uses **three parallel tracks** that proceed independently but converge:
    14→    14→
    15→    15→- **Releases** (v2.1, v2.2, ...) — user-facing feature deliveries, each produces a shippable build
    16→    16→- **Sprints** (Sprint 1, 2, ...) — infrastructure/RBAC work that enables platform-scale features
    17→    17→- **Migration Phases** (M1–M8) — zero-downtime migration from MVP to production SaaS platform
    18→    18→
    19→    19→A release may span multiple sprints. A sprint may contribute to multiple releases. Dependencies are explicitly mapped.
    20→    20→
    21→    21→```
    22→    22→Releases:      v2.0 ─── v2.1 ─── v2.2 ─── v2.3 ─── v2.4 ─── v2.5 ─── v2.6 ─── v3.0
    23→    23→                   \       \       \                \       \       \        \
    24→    24→Sprints:        S1+S2 ──  S3 ──  S3B ─── S4 ─── S5 ─── S6 ─── S7 ─── S8 ─── S9+
    25→    25→                                                                     \
    26→    26→Migration:                                             M1 ── M2 ── M3 ── M4 ── M5 ── M6 ── M7 ── M8
    27→    27→```

  1247→  1247→## Key Implementation Principles
  1248→  1248→
  1249→  1249→1. **Use Design Tokens** — All colors, spacing, typography from `lib/core/tokens/`
  1250→  1250→2. **Use Enterprise Components** — KlasivoButton, KlasivoCard, KlasivoBadge, etc.
  1251→  1251→3. **Use Feature Flags** — Gate new features AND migration steps behind flags
  1252→  1252→4. **Use Permission Gates** — `KlasivoPermissionGate`, `KlasivoRoleGate`
  1253→  1253→5. **Use Event Bus** — Decouple feature modules via typed events
  1254→  1254→6. **Follow Clean Architecture** — Services → Providers → Screens
  1255→  1255→7. **Soft Delete** — All entities use `isArchived` + `archivedAt` pattern
  1256→  1256→8. **Riverpod Functional Style** — Functional providers, not Notifiers (except where needed)
  1257→  1257→9. **Firestore Security** — Role-based rules with field-level security
  1258→  1258→10. **RBAC is Platform-Agnostic** — Permissions know role/permission/scope, not Web/Mobile/Dashboard
  1259→  1259→11. **Fail-Closed Authorization** — Missing metadata = DENY. Unknown scope = DENY. Empty arrays = DENY.
  1260→  1260→12. **Server-Side Role Determination** — Never trust client-sent role values; derive from auth claims
  1261→  1261→13. **Shared Models, No Duplication** — Monorepo packages ensure single source of truth for all apps
  1262→  1262→14. **Migration is Feature-Flagged** — Every migration step can be rolled back per-org without downtime
  1263→  1263→15. **Immutable Audit Trail** — Every mutation logged, append-only, no deletion
  1264→  1264→
