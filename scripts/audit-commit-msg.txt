fix(audit): 19 permission-denied queries + provider divergence

Comprehensive fix for the 19 failing Firestore queries identified in the
Klasivo permission-denied audit. Every query was missing the required
.where('organizationId', isEqualTo: orgId) filter for org-scoped list
queries — Firestore rules require isInSameOrg() / isInComingSameOrg()
which can only be satisfied if the query is scoped to the caller's org.

CRITICAL (Fix #1) — Student login completely unblocked:
  auth_service.dart:686 — loginStudent previously queried
    users.where('studentCode', isEqualTo: code).where('role', isEqualTo: 'student')
  which is a LIST query requiring isInSameOrg() — but at this point we don't
  yet know the user's orgId (it's stored IN the doc we're trying to fetch).
  Result: every student login was denied. This is why STU-YDETAN appeared
  on the teacher dashboard (getStudentsByOrganizationStream HAS the org
  filter) but couldn't log in.
  Fix: read the doc directly by the authenticated UID (.doc(uid).get()).
  Single-doc reads can be authorized via 'request.auth.uid == userId' — no
  orgId filter needed. Added defense-in-depth role check (Step 2.5) since
  the old list query had a role filter that the new single-doc read bypasses.
